# CANON.md —— 原著设定基准与逐项偏离清单

> **这个文件是干什么的**：`verify` / `branch_audit` / `passage_audit` / `continuity_audit` 全部只能查**内部自洽**。
> 它们永远查不出「不符合原著」—— 因为原著不在代码里。
> 所以设定符合度只能靠**人工核对 + 一张写下来的基准表**。这个文件就是那张表。

> **建立日期**：2026-09-11（v5.5 起草）
> **核对结论（v5.5）**：项目曾存在系统性偏离，其中两处伤及原著的情感核心。

## 0. 先定基准：以哪个为准？

《长安十二时辰》有**两个不同设定**的来源，且它们在关键处不一致：

| | 马伯庸原著小说 | 2019 剧版（曹盾导演） |
|---|---|---|
| 鱼肠 | **男性** | **女性**（李媛饰） |
| 烽燧堡幸存者 | 只剩**3 人**（闻无忌、萧规、张小敬） | 剩**8~9 人** |
| 张小敬左眼 | **瞎**（为救萧规被砍） | **没瞎** |
| 闻染结局 | — | 被鱼肠嫉妒逼得**跳井** |

**本项目没有声明以哪个为准，而且实际两边都不完全对**（例如鱼肠按剧版是女的 ✅，但她的地位按原著/剧版都不是"主事人" ❌）。

👉 **建议在 README 顶部明确写一句以哪个为准。** 不改基准，下面的表永远没法收敛。
（✅ 已在 v6.0 落实：README 顶部加了「设定符合度声明」，基准见第 0.1 节。）

### 0.1 v6.0 逐处择优决策（用户拍板："按原著还是电视剧，择优"）

用户要求修正所有偏离，并对每处"原著 vs 剧版"取更优者。决策如下（两版一致者直接统一，分歧者择优）：

| 偏离点 | 原著（小说） | 剧版（2019） | 本作取舍 | 理由 |
|---|---|---|---|---|
| 鱼肠性别 | 男 | 女（李媛） | **剧版·女** | 剧版形象已成经典，且本作此前已用女 |
| 张小敬左眼 | 瞎（为救萧规被砍） | 不瞎 | **剧版·不瞎** | 本作从未写瞎，保持一致 |
| 烽燧堡幸存 | 3 人（闻无忌/萧规/张小敬） | 8~9 人 | **两说并存** | 写"仅余数人（小说三、剧八九）"，核心三人必保留以支撑相认 |
| 闻染结局 | — | 跳井（被鱼肠逼） | **剧版作背景注脚** | 本作不抵达该结局，仅作人物关系底色 |
| 龙波＝萧规 / 第八团 / 入狱原因 / 灯楼兴庆宫 / 狼卫vs蚍蜉 / 阙勒霍多 | 同 | 同 | **两版一致→直接统一补全** | 情感核心，无分歧 |
| 王韫秀/王蕴秀 | 史：王韫秀+王忠嗣 | 剧：王蕴秀+王宗汜 | **剧版全一致→王蕴秀+王宗汜** | 原作混搭（名用史、父用剧），择一收敛 |

> 总基调：**以剧版为外观基准（鱼肠女、张小敬不瞎、王蕴秀+王宗汜），以原著为情感内核（第八团/烽燧堡/萧规相认/入狱真实原因/蚍蜉vs狼卫），两版一致处直接补全。** 不硬选单一来源。

## 3. 三条可选路线（**已拍板：v6.0 采纳路线 A**）

> **决策已定（2026-09-11）**：用户拍板走「路线 A · 全面对齐原著」，逐处择优见第 0.1 节，逐项修正落点见第 6 节。
> 下表保留为当时的决策依据，不再是开放问题。

| 路线 | 做法 | 代价 |
|---|---|---|
| **A. 全面对齐原著** | 补第八团／烽燧堡／闻无忌；让龙波在灯楼上与张小敬相认；闻染改为共谋者；引入蚍蜉与狼卫的区分 | 主线要大改：`h_hai` 对峙的整个情感基础要重写，4 个结局的措辞都要动。工作量最大，但只有它能真正"符合书籍设定" |
| **B. 只修事实错，不重构** | 删掉「狼卫首领」标签、灯楼位置改掉、鱼肠降回刺客、删掉 `x_xu_hear` 的编造独白 | 快，但**仍然是"借用人物名的另一个故事"**，不能声称"符合原著" |

**我的判断（仅供参考）**：如果目标是"**符合书籍设定**"，只有 A 能达成；B 是中间态；C 是诚实兜底。
**无论选哪条，都应该先把基准写清楚（第 0 节），否则无法验收。**

## 4. 为什么这件事没有工具能代劳

`verify` / `simulate` / `branch_audit` / `passage_audit` / `continuity_audit` 全都在检查**代码里已有的东西**：

- 它们能查「flag 有没有人读」「两段文本有没有重复」「时辰有没有跳」
- 它们**不可能**查「龙波该不该认识张小敬」——因为**原著不在这份代码里，任何自动检查都无法把自己的知识当作标准答案**

所以这一层只能：**人工核对 → 写成表 → 逐项判 → 人来拍板**。
这不是工具不够好，是这类问题**在原理上不可自动化**。任何声称"全绿"的自动化报告，都不覆盖这一层。
