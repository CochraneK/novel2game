## 玩法



- **顶栏十二时辰刻度**：当前时辰高亮，走过的自动点亮。

- 每个剧情节点含 2–4 个**关键抉择**（多数为 3 个，共 22 个剧情节点 / 66 个抉择），一个选项可以同时做这些事：

  触发跳转 / 打标记（flag）/ 获得线索 / 改变某角色信任度 / **为 6 个人格维度加分** / **为 MBTI 4 维加分**

- 选完之后，你会先走进一段**只属于这个选项的过场**，然后再汇合回主线。见下文「过场场景」。

- 走到 **亥时 · 抉择**（灯楼顶对峙龙波），根据你的 **同路人数** 与 **flag** 分流到 4 个结局之一。



### 过场场景（v5.4）



22 个抉择点里，**21 个**已经做到「每个选项把你带到不同的地方」；其中 **20 个**是「先走一段专属过场，再汇合回主干」。



过场是一个**新的节点类型**：非结局、**没有 `choices`**、只有一个 `next` 出口，引擎把它渲染成一个「继续」按钮。



```js

x_task_power: {

  id: 'x_task_power', hour: 'zi', place: '靖安司',

  pov: 'zhangxiaojing',

  text: `「给我人，给我权。我要在长安横着走。」

  李必没有立刻应。他看了你很久，那种看法你熟——是在算一个人值不值得放出去。

  最后他说了一个字：「准。」……`,

  next: 'h_zi2_gela',

  nextLabel: '走出靖安司。',

}

```



**过场不是抉择点**，这一点被三个地方同时保证（都走 `src/data/scenes.js` 导出的 `isPassage` / `nextTargets`，不许各工具自己抄一份）：



- 不推进 `state.choicesMade`，不累计 `traitRaw` / `mbtiRaw`

- 不参与 `nodeMax` / `mbtiNodeStats` 的**机会基线与满分**计算

- 不进 `branch_audit` 的「伪选择」分母



所以这一轮**没有新增任何抉择**（选项数仍是 66），人格与六维计分完全没动。



**写一段过场时的三条约定**（`tools/audit/passage_audit.mjs` 会盯着前两条）：



1. **不复述下一场戏。** 过场写「选择那一刻之后、下一场戏之前」发生的事。如果过场把汇合点的句子先说了，汇合点读起来就是重复。

2. **不复述上游抉择点的正文。** 玩家上一屏刚读过，过场再念一遍 = 原地踏步。（这条是通读 59 段时手抓出来的：`x_doc_confront` 照抄了上游 `h_si_doc` 里 34 个字。）

3. **不复述下游的条件插段。** 插段的活是"接住"，过场抢了它的台词，插段一进来就撞车。



还有一个约束继承自主线的共享性：**过场与它所在的节点，都不能断言"你有什么 / 谁在场 / 谁还活着"这类路径级或结局级事实。** 这一轮据此删掉了 `x_tail_help` 里的一句「你身上没有腰牌，也没有官凭」——它和 `x_doc_confront` 的「把靖安司的令牌亮出来」在同一条时间线上直接对立。



### 四种结局



| 结局 | 触发条件 | 一句话 |

|---|---|---|

| **血色长安** | 拔刀，且同路人 **≥ 3** | 你用刀守住了长安。代价是你自己。 |

| **火起长安** | 拔刀，但同路人 **< 3**，且没毁掉油罐 | 你想一个人守住长安。长安没能守住。 |

| **灯火如昼** | 选「我不为长安死。我为这些人活。」且同路人 **≥ 4** | 你守住的不是一座城，是城里的人。 |

| **未竟之局** | 选「龙波，收手吧」且**查过朝堂**；或选「我懂你」且**龙波信任 ≥ 20** | 你阻止了火，却没能阻止长安慢慢烂掉。 |



**同路人**＝除主角张小敬外，信任度 ≥ `ALLY_TRUST`（75）的角色数。



门槛是分级设计而非一刀切：拔刀要 3 人（乱选的众数附近，跟着走就扛得住），最好的结局「灯火如昼」要 4 人（得真的把人拉到身边），「未竟之局」则完全不看人数、只看你有没有看清朝堂那条线——**或者**你有没有先听懂龙波恨的是什么。所以「独行到底」会输，「广结人脉」「追查朝堂」「以情动人」各通向一个隐藏结局。



还有一处**中段选择改变结局**的设计：如果你在 `h_mao_tail` 支路选了「摸进去，先毁掉这些油罐」，西市那十七罐阙勒霍多就少了一半——**哪怕同路人不足 3 人，拔刀也能守住**（条件路由 `{ when: { flagsAll: ['try_destroy'] }, then: 'e_final_fight' }`）。



实测（3000 局随机）结局分布：血色长安 49.7% / 未竟之局 24.1% / 灯火如昼 18.4% / 火起长安 7.9%。

## 条件系统（v4 核心）



这是让「选择真正影响结局」的机制。条件键在**选项的 `require`** 与**跳转路由的 `when`** 里通用，语义完全一致。



### 条件键



| 键 | 含义 |

|---|---|

| `flagsAll` | 这些 flag **全部**已设置 |

| `flagsAny` | 这些 flag **至少一个**已设置 |

| `flagsNone` | 这些 flag **一个都没有** |

| `trust` | 指定角色的信任度 **≥** 给定值，如 `{ trust: { longbo: 40 } }` |

| `allies` | 同路人（信任 ≥ 75 的非主角角色）**数量 ≥** 给定值 |

| `clues` | 已获线索数 **≥** 给定值 |



### 两种用法



**① 选项门控** —— `require` 不满足的选项不显示，改为渲染一条灰色「未解锁」提示（`requireHint`），让玩家知道错过了什么、怎么拿：



```js

{

  t: '「我不为长安死。我为这些人活。」',

  flag: 'final_people', to: 'e_final_people',

  require: { allies: 4 },

  requireHint: '你身后得真的站着人 —— 需要至少 4 位同路人信任你',

}

```



**② 条件路由** —— `to` 可以是字符串（固定跳转），也可以是规则数组，取**第一个** `when` 成立的 `then`：



```js

{

  t: '「我愿意。」——拔刀，拼死一战。',

  flag: 'final_fight',

  to: [

    { when: { allies: 3 }, then: 'e_final_fight' },  // 身后有人，刀才有意义

    { then: 'e_burn_fire' },                          // 兜底：孤身一人，拦不住他

  ],

}

```



当前共 **5 个条件选项 + 1 处条件路由**。



### 条件的第三种用法：条件正文



条件键还能用在**正文**上，让同一段剧情因你来路不同而不同。这是把 flag 变成叙事后果的最低成本方式——**不需要新增任何节点**。



**① `inserts`（首选）** —— 往默认正文里插入段落，可多条叠加：



```js

{

  id: 's1_task', ...,

  text: `李必展开一卷长安舆图，手指落在西市。



……「你果然知道。」李必收起图，「十二个时辰。」……



{{inserts}}



窗外的更鼓响了一声。子时已过。`,

  inserts: [

    {

      when: { flagsAll: ['probed_first'] },

      text: '「还找过谁？」你又问了一遍。\n\n李必沉默了一息。「三个。一个死在平康坊，一个跑了，一个不肯接。」',

    },

  ],

}

```



**插入点由正文里的 `{{inserts}}` 标记决定**——标记写在哪，插段就落在哪。



> ### ⚠️ 为什么不用「塞最前 / 塞最后」

>

> 这是 v5.1 修掉的一个真 bug。早期实现让插段二选一：塞在正文第一个字之前，或者追加到末尾。

>

> 问题在于**节点正文往往以转场句开头**：

>

> ```

> 你出了靖安司，没有直接去查案。     ← 转场句

>

> 你绕进了一条暗巷——平康坊的地下暗市。

>

> 葛老……坐在一堆绢帛中间，正在喝茶。

> ```

>

> 插段一律塞在最前，就成了：

>

> ```

> 你还没去坊里，葛老却像早算到你会路过这儿。   ← 插段

> 「你要找的那姑娘，」他说……

>

> 你出了靖安司，没有直接去查案。              ← 正文转场句

> 你绕进了一条暗巷——平康坊的地下暗市。

> ```

>

> **先提到葛老，再说你走进葛老的暗市**——预告式倒叙。玩家读到的是「我说了话，但故事没接住」。

>

> 标记把插入点交给**正文结构**决定，而不是交给作者猜。



**两条硬规则**（`tools/audit/verify.mjs` 与 `tools/sim/simulate.mjs` 会盯着）：



1. **插段要写成"承接"，不能写成"预告"。** 它落在标记之后，所以读起来必须接着上一句往下走。

   - 反例：`你还没去坊里，葛老却像早算到你会路过这儿。`（标记在"你绕进了暗市"之后 → 自相矛盾）

   - 正例：`你没提闻染，葛老却像是早算到你会来问这个。`

2. **数组顺序 = 读者看到的顺序。** 多条插段是**同时生效**（不是多选一），所以按时间顺序排。

   典型事故：无条件插段写「十七桶」，条件插段写「只剩九只」——两条一起插入就打架了。



**② `textVariants`（备选）** —— 整段重写，取第一个匹配者。只在「整场戏基调都变了」时使用，因为它要复制全文，容易与默认正文失同步。



两者可叠加：先选变体，再把插段套上去。



### 这些机制的验收标准



一条选择是否"真的留了痕迹"，不是靠感觉，而是可测的：



- `npm run verify` —— 条件引用的 flag 必须真的有人设置（防「幽灵条件」）；每个节点必须至少留一个**无条件**选项（防死锁）；条件正文的 `when` 键名与引用合法；有插段的节点必须写 `{{inserts}}` 标记（漏写会退化成"追加到末尾"，会报警告）。

- `npm run audit:branch` —— 统计**死标记**（写了但没人读的 flag）与**无痕迹节点**（走向相同且所设 flag 无人消费）。目标是保持 0。

- `npm run test`（内含 `simulate`）—— 随机 3000 局的**插段叠加审计**：枚举"哪些插段会一起出现"。文字层面的矛盾（「十七桶」vs「只剩九只」）静态检查抓不到，只能这样枚举出来看。当前全剧最多只有 2 条同时生效。

- `npm run smoke:text` —— 用真实浏览器跑「总选第一项」vs「总选最后项」两条走法，比对共同节点的**渲染文本**。当前 19 个共同节点里 18 个正文不同（唯一相同的是 `start`，第一个节点前面没有来路）。

- `npm run dump -- last` —— 把一局完整流程按**玩家视角**打印成可读文本，用肉眼从头读到尾。脚本测不出"读起来通不通"，只能看。支持 `first` / `last` / `random 7` / `seq 1,1,2,1`（按序号走指定支路）。

- `node tools/sim/trace_choices.mjs` —— **逐选项追问「选完之后紧接着读到什么」**。每个选项打印：写到哪些 flag → 目标节点 → **该选项真正命中的那段插段** → 后文有没有读这个 flag。这是唯一能把"我的选择被后文接住了吗"摊开看的视图；`--brief` 只看摘要，加节点名只看单个节点。

  （完整结果可以导出留档：`npm run trace > reports/choice_trace.txt` —— v5.3 就是靠通读这份 800 行对照表找出那 3 处"接不住"的）



> ⚠️ **重要**：被 `require` 挡住的选项**不参与人格计分上限的计算**。`nodeMax` / `mbtiNodeStats` 都按「当前实际可选的下标集合」归一化，否则选项一少，达成率就会虚高。

## 人格测评：MBTI



### 4 个维度（映射到长安语境）



| 维度 | 左 / 右 | 长安语境 |

|---|---|---|

| **E / I** | 外向 / 内向 | 调兵遣将广结人脉 ↔ 独自追查深思独行 |

| **S / N** | 实感 / 直觉 | 查户籍看脚印重物证 ↔ 推断动机看朝堂大局 |

| **T / F** | 思考 / 情感 | 就事论事冷酷决断 ↔ 顾及人情宽恕共情 |

| **J / P** | 判断 / 知觉 | 守计划执行到底 ↔ 见机行事随机应变 |



- 每个抉择在 4 个维度各有 **-3 ~ +3** 的倾向分（正值偏 E/S/T/J，负值偏 I/N/F/P），共 66 个选项权重全覆盖。

- 结局页按**偏好强度**显示双向百分比条，如 `E 68% / I 32%`。

- 每维取较高一侧，组合成 **4 字母类型**（如 `ENTJ`）。



### 计分模型：机会基线归一化



朴素做法（「得分数 ÷ 满分」）在这个剧情树里会**系统性失真**：不同分支路过的节点数不同、可选选项数不同，某些维度在某些分支上根本拿不到负分，结果就是所有人都被推向同一侧 —— 旧版实测随机乱选会得到 **E 80.5% / I 19.5%、T 16% / F 84%** 这种严重偏斜。



v4 改为**机会基线归一化**：先统计每个维度在本局**实际经过**的节点上「可达到的均值 / 上限 / 下限」，再看你的得分相对均值往哪边偏了多少：



```

dev     = 得分 - 均值

upRoom  = 上限 - 均值      # 往上还有多少空间

downRoom= 均值 - 下限      # 往下还有多少空间



dev > 0 且 upRoom  > 0  →  左侧占比 = 50 + 50 × min(1, dev / upRoom)

dev < 0 且 downRoom > 0  →  左侧占比 = 50 - 50 × min(1, -dev / downRoom)

上下都没有空间（spread ≈ 0）→  该维度无法判定，标为「无偏好」

```



这样 **50% 线严格等于「和机会均值的偏差为零」**，左右两侧天然等概率。



### 平局怎么处理



旧版存在一个自相矛盾：进度条显示 50/50，字母却硬判给右侧。v4 显式区分三种状态：



- **有偏好**：正常给出字母与百分比

- **无偏好（tie）**：偏差恰好为 0 → 标为「无偏好」，并在结局页注明

- **无法判定（none）**：该维度全区间无可达空间 → 同样注明



实测 3000 局随机：**5.4% 的对局至少有一个维度落在 50/50**，且都会被如实标注。

### 匹配逻辑（三层）



1. **主匹配**：与你 MBTI 型相同的人物（16 型 ↔ 16 人物确定性对应，零重复）

2. **契合度**：你的四维强度与该人物向量的平均偏差 → `契合度 76%`

   - 高 = 你是这个型的「典型样本」；偏低 = 你处在这个型的边缘

3. **次席**：比较「特质形状」给出第二接近的人物，作为补充视角



### 长安六维（辅助画像）



结局页另附 **6 维长安人格**（义气 / 谋略 / 仁恕 / 胆魄 / 信义 / 执念），用于剧情化解读与「最相似角色」，与 MBTI 互为补充，不是独立测评。

## ⚠️ 这个测评科学吗？——如实说明



**结论：作为心理测量工具，它不科学，请不要当作人格测验使用。**



上面的统计修复（机会基线归一化、平局标注）只解决了**计分是否自洽**，没有、也不可能解决**测量是否有效**。这是两件事，容易被混淆，所以下面分开讲。



### 它不成立的地方（按严重程度）



| # | 问题 | 说明 |

|---|---|---|

| 1 | **构念效度缺失** | 题目是「剧情里的决策」，不是「关于你自己的陈述」。没有任何证据表明「在唐代危机里会不会拔刀」能预测现实中的外向性。没有效标关联效度，没有与任何成熟量表（BFI-2 / NEO-PI-R）的聚合效度检验。**这是最根本的缺陷，其余问题都在其次。** |

| 2 | **权重是作者按「叙事合理性」手工指定的** | 没有因子分析、没有项目校准、没有专家评定、没有 IRT。所以「拔刀 = +2 E」只是一个文学判断，不是测量参数。我们因此无法知道这 66 道题究竟测到了几个维度。 |

| 3 | **没有常模样本** | 结果里的 `E 68%` **不是百分位**。它只是相对「本局机会基线」的线性重标定，没有人群参照。所以不能说「你比 68% 的人更外向」，只能说「你在这局里的作答偏离随机基线多少」。跨人比较在统计上是无意义的。 |

| 4 | **人物「契合度 %」是循环论证** | 我们先给 16 位角色手工编写了「人格向量」，再去衡量你和这些向量的距离。参照系是我们自己编的，因此这个百分比没有任何外部依据。 |

| 5 | **把连续变量切成了类型** | 这是 MBTI 本身的原罪，我们也继承了。详见下节。 |



### 我们实测到的统计性质（有好有坏）



用 `npm run audit` 可复现下面每一个数字：



**✅ 做得还行的地方**



> 以下数字由 `npm run audit` 实测得出。它是蒙特卡洛抽样，同一份代码每次运行会有小数点后的浮动。



- **分布形状是对的**：结果百分比呈单峰钟形，中心在 50，标准差 12.5~13.6，**极端值（0% / 100%）出现率 0.0%**——符合「多数人的特质在中间」这一真实特征，没有出现把所有人推向两极的人造现象。

- **4 个维度基本正交**：跨维度最大相关仅 **r = 0.10**（EI~JP），远低于 0.3 的独立判据。说明这 4 个维度在权重层面确实是可分的，没有退化成一两个维度。

- **对单题扰动稳定**：只改 1 个回答时，4 字母类型一致率 **约 93%~95%**，单维度一致率约 98%（蒙特卡洛估计，每次运行略有浮动）。



**❌ 站不住的地方**



- **S/N 维度题量不足**：66 道题里只有 **20 道**在 S/N 上有信号（E/I 有 35 道）。该维度的测量精度明显低于其他三维，值得后续补题。

- **路径依赖污染基线**：因为不同分支经过的题目不同，**「机会基线」本身会随路径漂移**。换算成测量噪声：

  - E/I ≈ 1.6 个百分点，S/N ≈ 2.4，T/F ≈ 0.6，**J/P ≈ 3.1**

  - 对照量表本身的标准差约 13.0，J/P 这条噪声占了约 **25%**。

  - 正规模表里每个人做的是同一套题，这条噪声应当为 **0**。这是本设计特有的结构缺陷。

- **超过一半的题是「复合题」**：**55%**（36/66）的选项会同时改动 ≥2 个维度，单题最多同时改 3 个。测量学上这叫 double-barreled item——无法归因到底是哪一个维度在被测量。

- **约 57% 的维度落在脆弱区**：落在 40%~60% 这个「差一两个回答就会翻面」区间的维度占 **约 57%**。加上我们的标准差（12.5~13.6）比真实量表（15~20）更窄，说明分数被压缩在中间，字母判定的边界稳定性偏低。



### 关于「类型」这件事本身



真实的人格特质在人群中是**连续且单峰**的，大多数人落在中间，而不是分成两堆。所以「你是 E 还是 I」这种二分，本质上是**对连续变量做中位数切分**的产物——切点附近的人，换几个答案就会换类型。



这也正是经典 MBTI 最大的实证问题：



- **重测信度差**：4~5 周后重测，约 **50%** 的人会拿到完全不同的 4 字母结果（Pittenger 1993，后续多项研究复现）；单个维度一致率约 65%~85%。

- 对照：**大五人格**（NEO-PI-R / BFI-2）的重测相关 r ≈ **0.70~0.85**，且维度是连续的、有效度证据充分。



我们的「隔一阵子再测」模拟（让被试的潜在倾向小幅漂移）结果（`npm run audit` 实测，蒙特卡洛抽样，每次运行有 ±2 个百分点左右的浮动）：



| 倾向漂移 σ | 类型一致率 | 单维度一致率 |

|---|---|---|

| 0.10 | ≈89% | ≈97% |

| 0.20 | ≈80% | ≈94% |

| 0.30 | ≈72% | ≈92% |

| 0.50 | ≈56% | ≈87% |



σ 表示「两次作答之间这个人变了多少」。可以看出：**一旦人自身有小幅变化（σ=0.5），类型一致率就掉到 56% 左右**，与真实 MBTI 的重测表现量级相当。二分法本身就在放大不稳定性。



### 那它有什么用？



有，但不是「测评」：



- **作为游戏机制**，它是称职的：它让 66 个选择汇成一个个性化的收尾，并与结局门控联动，这是设计上的成功。

- **作为自我觉察的引子**，可以——前提是把它读成「你这局是怎么行动的」，而不是「你是什么样的人」。

- **作为教学样例**，很适合：它现场演示了「把连续特质二分」会带来什么后果。



### 想真正做测量该怎么做



1. 换成**连续计分**，报告维度分与标准误，不报类型码。

2. 建**常模样本**（哪怕几百人），把原始分转成百分位。

3. 做 **EFA / CFA**，用数据而非直觉确定维度数与题目归属；删掉 double-barreled 题。

4. 与 **BFI-2 / IPIP-NEO** 做聚合与区分效度检验。

5. 改测**大五**而非 MBTI——构念本身效度更好，且已有大量公开题库（IPIP 属公有领域）。

6. 若要临床或科研使用，请用**经过验证的工具**（NEO-PI-R、BFI-2、PID-5 等），本工具不具备任何诊断资格。

### 架构约定



- **数据与引擎分离**：`src/data/*.js` 是纯数据模块（无副作用、无 DOM 依赖），`src/main.js` 是引擎。数据模块可被 Node 测试脚本直接 `import`，因此 `verify.mjs` / `simulate.mjs` 不需要浏览器就能跑。

- **零运行时依赖**：`package.json` 里的 `playwright` 相关只服务于测试，`src/` 下不 import 任何第三方包。

- **改选项顺序必须同步改权重**：`scenes.js` 里某个节点的选项增删或换序后，`traits.js` 的 `CHOICE_TRAITS` 与 `mbti.js` 的对应权重表必须同步改下标，否则 `verify` 会报错。这是刻意设计的 —— 让错位在 CI 里立刻暴露，而不是静默算错分。

### 人工审阅为什么不能省



`verify` / `simulate` 只能证明**结构**没错——节点连通、flag 有人读、结局可达、权重覆盖。它们证明不了**读起来通不通**。



v5.1 修掉的那个「预告式倒叙」就是结构全绿但没法读的典型：节点连通、flag 都被消费、测试全过，但玩家读到的是「先提到葛老、再说你走进葛老的暗市」。



v5.2 又抓到一类**只有在整条线读完才看得见**的毛病：



| 症状 | 为什么自动化检查抓不到 |

|---|---|

| `h_hai` 正文说「他们全都上来了」，可达的 `e_burn_fire` 却说「你身后没有人」 | 单看任一段都通顺，矛盾跨节点 |

| 结局写「你想起闻染说的话——长安不用你守」，但**这句台词全剧从未出现** | 要在全库范围检索才知道它只出现这一次 |

| `h_wei` 标 `pov: 'libi'`，侧栏显示「李必视角」，正文却是「李必从屏风后走出来」 | 元数据与正文的一致性，跨字段 |

| `h_shen` 正文写「伤口在流血」，但可达的 `observe` 支路里你根本没动手 | 同上，跨节点 |



所以 `tools/smoke/dump_play.py` 是必需的：它把真实浏览器渲染出来的每一段按顺序打印，像读者一样从头读到尾。



v5.4 又抓到第四类：**过场在复述。** 这一轮给 21 个抉择点的每个选项都加了一段专属过场，于是出现了新的失败模式——过场把上一场或下一场的话又念了一遍。



| 症状 | 为什么自动化检查抓不到 |

|---|---|

| `x_task_lone` 结尾写「身后没有人。」，汇合点 `h_zi2_gela` 的插段写「你身后一个人也没有。」 | **换了说法**的重复，字面最长公共子串只有 5 字 |

| `x_wu_doc` 让崔器把「边军冬衣」念第三遍（基座正文念过、玩家选项里念过） | 三次分散在三个字段里，要连起来读才发现 |

| `h_wu` 的选项 4 说「调拨单上写的是『边军冬衣』」——可 `h_wu` 的基座正文里崔器**自己**已经说了同一句 | 选项文案与基座正文的矛盾 |

| `x_gela_power` 选了「亮靖安司腰牌」，过场却从「你办完事」写起，**把玩家刚点的那个动作整个跳过去了** | 结构上完全正常，只有读到才发现"我点的那一下没演" |

| `x_tail_help` 写「你身上没有腰牌，也没有官凭」，`x_doc_confront` 写「把靖安司的令牌亮出来」 | 两条路径在同一条时间线上，跨节点对立 |



为此新写了 `tools/audit/passage_audit.mjs`（`npm run audit:passage`）：把每段过场与**三个对象**逐一比对——上游抉择点、汇合点、两处的条件插段。度量用**最长公共子串**（抓照抄）+ **三元组重合系数**（抓"换了个字"的重复，例如「文书你先送回**了**」vs「文书你先送**去**了」）。



> 这个工具本身也是被通读逼出来的：第一版只比下游汇合点，结果漏掉了 `x_doc_confront` 照抄上游 `h_si_doc` 整整 34 个字——**过场最容易复述的不是下一场戏，是上一场戏**。



**改完正文必须跑这几条：**



```bash

npm run dump -- last        # 从头读到尾，看有没有接不住的句子

npm run dump:endings        # 4 个结局各读两遍（同路人拉满 / 一个都没有）

npm run audit:passage       # 过场有没有在复述上游 / 汇合点 / 插段

node tools/audit/passage_audit.mjs digest > reports/passage_digest.txt   # 逐对人工通读

```



`endings` 模式之所以必要：4 个结局是同一个分流点（`h_hai`）的四个出口，而 `h_hai` 之前的 22 个节点**全部**能走到这 4 个结局。也就是说主线是共享的——**改任何一段主线正文，都得回来把这 4 段并排读一遍**，确认没有哪一句被某个结局当面否掉。该模式还会断言渲染结果里没有 `{{inserts}}` 标记残留（主引擎曾经直接读 `sc.text`，导致结局的插段不渲染、标记原样显示给玩家）。

## 交互与无障碍



- **键盘**：`1` `2` `3` 直接选择对应选项；结局浮层上按 `Enter` / `空格` 关闭。

- **焦点**：所有可交互元素都有 `:focus-visible` 样式；结局浮层打开时会把焦点移到关闭按钮。

- **读屏**：结局浮层带 `role="dialog"` 与 `aria-hidden` 状态切换。

- **移动端**：侧栏在小屏改为**抽屉式**侧滑面板（`transform: translateX`），不再用 `display: none` 直接隐藏 —— 否则手机上会看不到「同路人」，而结局正是按同路人判定的。顶栏有开关按钮。

- **动效**：尊重 `prefers-reduced-motion`，关闭过渡动画。

- **字体栈**：Windows 优先（思源宋体 / 微软雅黑 等），带跨平台回退。

- **图标降级**：CDN 图标加载失败时自动加 `.no-icons` 类，走纯文字排版，不会出现空白方块。



### 调试钩子



URL 加 `?debug=1` 会暴露内部状态，供集成测试按「结论」驱动剧情：



```js

window.__changan = { state, countAllies, evalCond, resolveTo, scenes, characters, ALLY_TRUST,

                     goto(id),      // 跳到某个节点/结局并渲染

                     setTrust(obj) } // 直接设定信任度，用来构造极端局面

```



例如 `smoke_gate.py` 用它算出「本局怎么选才能把同路人拉到 5」，再照此走完，从而稳定地分别触发不同结局。



`goto` / `setTrust` 是给 `npm run dump:endings` 用的：结局只有走到才能看见，而它恰恰是条件插段最密的地方（`e_final_people` 有 5 条），手工复现成本太高。

   穷举 13,608 条到 `h_chen` 的来路：**11,664 条（86%）根本没报过**，这 86% 会读到一句凭空出现的汇报。

   → 正文里那句删掉，改成两条**互斥**插段：

   `flagsAll: ['reported']`（"西市的消息，你方才已经递回来了"）／`flagsNone: ['reported']`（"你把西市那一趟说了一遍"）。

#### 二·补 — 让"正文断言了不存在的事"变成可自动检测



上面这些矛盾的形状是同一个：**正文写死了一个只在部分来路上成立的事实**，而该节点**本来就有插段**在管这件事。

所以问题不是"没人接住"，而是"正文自己也断言了一遍"：插段变成废话，没插段的那条路变成矛盾。



`passage_audit` 只比"过场 ↔ 下游/上游"，**不比"本节点正文 vs 来路条件"** —— 这就是漏网的原因。

给 `continuity_audit` 加了第 ⑤ 节：



- 用状态可达性 `(node, hasFlag)` 在 **85 × 2 = 170 个状态**上做可达性（不是穷举 1,300 万条路径，但结论等价）。

- 对每个"有插段依赖它"的 flag 问：**到达该节点时它是不是必然的？**

- 非必然 ⇒ 「没有它」的那条来路必须读得通。再判这条来路有没有被接住：

  - 有 `flagsNone: [F]` 的插段 → 已接住

  - 或 F 的**互斥兄弟**（同一抉择点其它选项的 flag）各有插段 → 已接住（兄弟互斥，"没有 F"必然落到某个兄弟身上）

  - 都没有 → ⚠️ **请看**

- 当前结果：**67 组候选：已接住 63 · 已人工确认 4 · 请看 0**。



**关键设计：工具抓不全，所以它必须能被"人工确认"结案。**

工具没有能力判断"正文那句话算不算断言了 F 代表的事"，所以它只负责**把范围从"85 个节点全读一遍"缩到几条**。

剩下那几条必须有人通读、并把结论写进工具里的 `CONFIRMED_OK` 表（带理由）——

不写下来 = 下次跑还是红的；写下来 = 下一个人知道"这条被谁、按什么标准放过了"。

这不是绕过检查，是**把人的判断变成可追溯的记录**。



第 ⑤ 节还顺手抓到一处此前的漏网：

`h_si_doc` 的 `cold` 插段写「**你没打算看**。……推过来的东西，你不接，它就一直在那儿。」紧接着正文却是「**你翻开文书**」—— 前后顶住了。

→ 插段结尾改成「你盯了很久。最后还是伸手把它拿了过来。」，让"不接"到"翻开"之间有一个动作。



**反向验证（证明它真能抓住第 4 处那种 bug）**：把 `h_chen` 那条 `flagsNone: ['reported']` 的兜底插段临时改成永不成立，

工具立刻报出 `[h_chen] flag「reported」不是必然 —— 有的来路有它、有的没有。正文开头: 辰时。靖安司。…`，退出码 1；恢复后转绿。



#### 三、这一层为什么没有工具能代劳



`verify` / `simulate` / `branch_audit` / `passage_audit` / `continuity_audit` 检的全是**代码里已有的东西**。

它们**不可能**回答"龙波该不该认识张小敬"—— 原著不在这份代码里，任何自动检查都无法把自己的知识当标准答案。

所以设定符合度只能：**人工核对 → 写成表 → 逐项判定 → 人来拍板**。

**这不是工具不够好，是这类问题在原理上不可自动化。任何声称"全绿"的自动化报告都不覆盖这一层。**

### v5.3 (2026-09-11) — 「选完之后，紧接着读到什么」



起因：玩家追问「**目前的选择连贯吗**」。v5.2 已经证明了"结构上连得起来"（flag 有人读、结局可达、没有死标记），但那只回答了"选择**有没有**后果"，没回答"**选完之后那一段，是不是真的接住了这个选择**"。



于是新写了一个工具 `tools/sim/trace_choices.mjs`，把 22 个选择节点逐条摊开：**每个选项 → 写到哪个 flag → 目标节点 → 该选项真正命中的那段插段 → 后文有没有引用这个 flag**。然后人肉读完 66 个选项的「紧接着读到」。



结论：**接线是通的**（66 个 flag 里 62 个被后文读取，0 个真死标记；三条主要走法的收尾确实不同），**但有 3 处接不住**，全部修掉：



1. **门槛卡在两个可达值中间，而提示描述的是走不通的那条**（`h_hai` 选项 4）

   选项要求 `trust.longbo >= 30`，但龙波初始信任 0，全剧只有两处给他加信任，且**都在 `h_xu` 里互斥**：

   · `hear_longbo`「你恨的到底是什么？说清楚。」 **+20**

   · `sympathize`「长安不是欠你的。但你的仇，我记下了。」 **+35**

   而 `requireHint` 写的是「需要先在灯楼听懂他恨的到底是什么」—— 描述的正是 **+20** 那条。

   玩家照着提示走，信任变成 20，**门还是锁着**。

   → 门槛改成 **20**。两条"理解他"的路这才都真的走得通（已实测：+20 解锁 ✅、+35 解锁 ✅、0 保持锁定 ✅）。



   这类 bug 的可怕之处是"看起来门槛是可达的"（35 ≥ 30），静态检查很容易放过。

   为此给 `verify` 加了一条**新判据**：**门槛卡在两个可达值中间**就报警，并直接列出"哪条够、哪条不够"，逼你回头确认 `requireHint` 描述的是"够"的那条。



2. **一个出口有两条来路，开场却只写了一条**（`e_final_persuade`）

   `h_hai` 的第 3、4 选项都通向 `e_final_persuade`，但结局正文第一句是

   「**「龙波，」你说，「我替你把仇报了。」**」—— 这是第 3 个选项的台词。

   选了第 4 个选项（「我懂你。但你杀的不是仇人。」）的玩家，会读到自己**从来没说过**的一句话。

   → 拆成两条互斥开场插段：`flagsAll: ['final_empathy']` 走"理解"版，`flagsNone: ['final_empathy']` 兜底走"承诺"版。

   `final_empathy` / `final_persuade` 在 `h_hai` 里天然互斥，所以 `flagsNone` 能安全兜底。



3. **后文紧接着做了一个你刚拒绝的动作**（`h_si_doc` 选项 3）

   选「现在不是说这个的时候。长安要没了。」之后，基座正文下一句是「**你翻开文书。**」

   基座正文对三条来路**不是都成立**：

   · 选 1「接过文书，当场翻开」→ 成立，而且正是这个选择的动作

   · 选 2「我给你一个交代」→ 她推过来，成立（插段已交代）

   · 选 3「现在不是说这个的时候」→ 你刚拒绝，下一句自己翻开 = 硬拐弯

   → 给 `cold` 插段补了过渡：她没收回手，把文书往你这边推了半寸 ——「推过来的东西，你不接，它就一直在那儿。」



**顺便修正：`trace_choices` 自己的输出曾经在骗人。** 它早先只看得懂 `flagsAll` / `flagsAny`，读到 `flagsNone` 兜底插段时就跳过，于是把 `e_final_persuade` 的"基座"显示成第 4 句——看起来像"选项 3、4 读到同一段"。其实它压根没模拟条件。改成三值逻辑（`true` / `false` / `null = 取决于前面的玩法`）之后，才正确显示选项 3 → `ins#1`、选项 4 → `ins#0`。

**审计工具本身也会撒谎** —— 工具报"全绿"的时候，得先确认它真的看懂了数据。



**新增工具**：`node tools/sim/trace_choices.mjs`（`--brief` 只看摘要，或 `node tools/sim/trace_choices.mjs h_hai` 只看某节点）

### v5.2 (2026-09-11) — 系统性复查：把"跨节点的矛盾"找出来
